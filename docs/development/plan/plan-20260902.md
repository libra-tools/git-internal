**模板版本:** v2.2，參照 ../libra/docs/development/plan/plan-template.md（核對日 2026-09-03，以該版條文為準）。

本文依 R11 至 R22 外部 review（Codex + Claude Code 雙 reviewer 循環，2026-09-03）修訂，R21 起雙 reviewer 均為 PASS；執行階段每張卡另按 ER-05 由 Codex review（review log R23 起）：按 G-08 以 REL-01 登記家族發布、修正實施順序邊、拆出 B3-02b、修正測試 filter 與 fixtures 事實、補齊 Cargo.lock 寫集與發布流程步驟、新增 ADR-GI-B3-05/06 與 EX-01 門族型 waiver 登記。

## 文檔職責

本文規劃在 git-internal 中增加 BLAKE3-256 作為 repository object ID 的完整支持，並交付可供 Libra 後續接入的穩定 API、pack/idx 行為、協定契約與相容性證據。

本文只規劃任務，不宣稱 Rust 實作已完成。每個任務開工時必須重新刷新源碼錨點。

### 適用範圍

- HashKind、ObjectHash、HashAlgorithm 及其解析/序列化 API。
- Blob、Tree、Commit、Tag、Note 與 AI object 共用的 object ID 邊界。
- loose object 相關 hash、pack decode/encode、pack trailer、ref-delta、idx 與 index 驗證。
- smart protocol 的 object-format 協商與 BLAKE3-only 兼容行為。
- 單元、pack round-trip、協定與相容性測試，以及 git-internal 文檔。
- 向 Libra 與 Monoengine 的明確移交契約。

### 非目標

- 不修改 ../libra 或 ../monoengine 的程式碼；下游接入由 DEP-OUT-01 移交。
- 不把既有 SHA-1 或 SHA-256 repository 原地切換成 BLAKE3。
- 不改變 AI IntegrityHash 的固定 SHA-256 語義。
- 不承諾未修改的標準 Git 能與 BLAKE3 repository 互通；標準 SHA-1/SHA-256 協定行為必須維持。
- 不把 Buck manifest、策略 digest、HMAC 或其他應用層 digest 改成 BLAKE3。

### 成功定義

- git-internal 可配置 HashKind::Blake3，計算、解析、顯示與序列化 BLAKE3-256 object ID。
- BLAKE3 repository 的 object、tree/commit 引用、pack trailer、ref-delta、idx v2 round-trip 全部正確；BLAKE3 對 idx v1 fail-closed。
- BLAKE3 與 SHA-1/SHA-256 的 32-byte/64-hex 歧義不再由長度隱式解決。
- smart protocol 可明確協商 object-format=blake3；不支持的 peer 以可診斷錯誤失敗。
- 舊 SHA-1/SHA-256 測試與輸出不回歸，AI IntegrityHash 仍固定 SHA-256。
- 本計劃所有非延後任務完成，全部驗證命令有證據，最終全量收口門全綠，並完成 DEP-OUT-01 的 Libra/Monoengine 移交文件。
- 計劃完成時只發布一次 `v0.9.0`；B3-01 至 B3-07 不產生中間版本，family child 仍各自以 Libra 本地 commit（不 bump、不 tag、不 push）；Cargo.toml/tag/crates.io artifact parity 已由 Libra 與既有 workflow 驗證。

## 評審結論與修訂記錄

計劃自審結論：

| 維度 | 結論 | 修訂動作 |
|---|---|---|
| 合理性 | BLAKE3 需求由 Libra 版本管理流程驅動，值得作為原生 repository format 支持 | 限定本計劃只交付 git-internal，以下游移交分隔 |
| 可行性 | 32-byte pack/idx 路徑可沿用部分現有抽象，但 ID 歧義、protocol 與窮舉 match 必須先處理 | 先做 API/object/pack precondition，再啟用 enum variant |
| 任務卡粒度 | 每卡一個行為軸，生產文件不超過 M 上限；protocol 與 pack 分開；最終發布獨立成 B3-08 | 以 B3-01 至 B3-08 與 B3-02b 建立 DAG；AC 按獨立謂詞、VER 按獨立驗證門計數，超限處登記 EX-01 |
| 依賴與順序 | DAG 無環；B3-02/B3-03 可在 B3-01 後並行，B3-02b 與 B3-04 之後串行；卡內 Dependencies 只引用 Task ID，ADR 作為 B3-00 的產物契約 | 在任務 Dependencies 與實施順序同步登記 |
| 完整性 | 涵蓋 parser、object、pack/idx、protocol、測試、文檔與下游移交 | 新增 GAP-01 至 GAP-07、測試矩陣與故障恢復矩陣 |
| 安全性 | 未知演算法、混合 repository context、pack checksum mismatch 均 fail-closed | ADR-GI-B3-02、ADR-GI-B3-03，並在 B3-05/B3-06 驗收 |
| 功能正確性 | 保留 SHA-1/SHA-256；BLAKE3 不靠 64 hex 長度猜測 | ADR-GI-B3-01、B3-01、B3-04 |
| 接口兼容 | 既有 raw Display 不變；新增帶 kind 的 parser/tagged representation | ADR-GI-B3-02，B3-04 |
| 數據流與控制流 | thread-local 僅作既有預設；跨執行緒/跨 repository 解析必須傳入 kind | GC-02、B3-01、B3-02 |
| 性能與容量 | BLAKE3 仍為固定 32 bytes；不得引入無界配置或重複整體 buffer | GC-10、B3-04、B3-05 |
| 可靠性與容錯 | pack/idx、stream、ref-delta 與 unknown protocol format 都有失敗路徑 | B3-05、B3-06、故障恢復矩陣 |
| 可維護性 | digest 分派集中在 hash/utils，呼叫端不再自行複製 SHA branch | B3-01 至 B3-03 |

## 已決議設計決策

### ADR-GI-B3-01: BLAKE3 作為新的 repository object namespace

- **Status:** Accepted
- **Context:** BLAKE3-256 與 SHA-256 同為 32 bytes；既有 object graph 的 tree、commit、tag 會內嵌 object ID。
- **Decision:** 新增 HashKind::Blake3 與 ObjectHash::Blake3([u8; 32])。BLAKE3 repository 是獨立 namespace；既有 SHA-1/SHA-256 repository 不原地切換。
- **Alternatives considered:** 將 BLAKE3 當成 SHA-256 的替代實作會造成 collision namespace 與 pack/idx 驗證錯誤；重新計算所有舊 refs 作為隱式 migration 不可回滾，因此拒絕。
- **Consequences:** Libra 必須在 repository 建立時固定 core.objectformat=blake3；跨格式轉換必須是顯式工具或雙 ID 映射。
- **Revisit when:** 標準 Git 或上游協定正式提供 BLAKE3 object format，或 Libra 決定提供可驗證的 repository conversion 工具。

### ADR-GI-B3-02: repository context 與外部 tagged ID 分離

- **Status:** Accepted
- **Context:** raw 64-hex ID 無法單獨區分 SHA-256 與 BLAKE3。
- **Decision:** object graph 內的 raw hex 與 loose path 維持現有 Git-like 表示；新增 ObjectHash::new_for_kind、from_type_and_data_for_kind、from_hex_for_kind、from_bytes_for_kind、from_stream_for_kind，以及 from_tagged_str/to_tagged_string 等顯式 API。需要跨 repository、API、日誌或索引攜帶演算法時使用 sha1:HEX、sha256:HEX、blake3:HEX tagged 表示。既有 ObjectHash::from_str 的 40/64 相容語義不得被靜默改變。
- **Alternatives considered:** 讓 from_str 依 thread-local kind 猜 64 hex 會讓外部 SHA-256 ID 在 BLAKE3 context 下被誤解析；讓 Display 改為帶前綴會破壞 loose path、tree/commit bytes 與既有 API，均拒絕。
- **Consequences:** 所有 repository 內部解析點必須傳入或持有 HashKind；下游資料庫/API 若可能跨格式存放 ID，必須保留演算法欄位或 tagged string。from_bytes_infer_kind 的 legacy contract 固定為 20 bytes=SHA-1、32 bytes=SHA-256；待 B3-05 清零 production caller 後加上 `#[deprecated]`，且不得用於 repository/pack/protocol 任何新路徑。
- **Revisit when:** ObjectHash 改為帶 algorithm metadata 的不可歧義 wire type，且 Libra/Monoengine 已完成 API migration。

### ADR-GI-B3-03: BLAKE3 pack/idx 與 protocol 邊界

- **Status:** Accepted
- **Context:** pack object bytes 與 ref-delta 的 hash width 可為 32 bytes，但 idx v1、現有協定 capability 與標準 Git 相容面不是 BLAKE3-aware。
- **Decision:** BLAKE3 只寫入/讀取 idx v2；pack trailer、ref-delta base ID、idx object name 與 checksum 使用 BLAKE3。Pack、PackEncoder、PackStats、IdxBuilder 與 object loader 以顯式 HashKind 建立 hasher/解析器。RepositoryAccess 增加帶預設實作的 object_hash_kind()，SmartProtocol 建立與每次傳輸前驗證 local/wire/repository 三者一致。smart protocol 增加 object-format=blake3 的明確協商；parse_capabilities 以 Result 回報 unknown/mismatch，fail-closed。
- **Alternatives considered:** 以 hash length 推斷 idx/protocol format 會把 SHA-256 與 BLAKE3 混淆；以 SHA-256 capability 偽裝 BLAKE3 會產生不可驗證資料，拒絕。
- **Consequences:** 未修改的標準 Git peer 不被宣稱支持；Libra-only transport 必須檢查 capability 與本地 repository format。wire 只傳 raw hex，tagged ID 僅用於 API/索引/日誌等非標準 wire 邊界。
- **Revisit when:** 有正式、可互操作的 BLAKE3 Git object-format 規範。

### ADR-GI-B3-04: AI IntegrityHash 維持 SHA-256

- **Status:** Accepted
- **Context:** AI object 的 IntegrityHash 是跨 repository format 的完整性欄位，已有固定 SHA-256 語義。
- **Decision:** 只改 Git object ID；IntegrityHash、既有安全策略 digest 與外部固定 SHA-1 契約不隨 repository HashKind 改變。
- **Alternatives considered:** 以 repository HashKind 計算 IntegrityHash 會使相同 AI artifact 在不同 repository format 下產生不同安全語義，拒絕。
- **Consequences:** 文檔與下游 API 必須區分 ObjectHash 與 IntegrityHash。
- **Revisit when:** 另有獨立的 IntegrityHash algorithm-version RFC。

### ADR-GI-B3-05: BLAKE3 cache spill 路徑的 kind namespace

- **Status:** Accepted
- **Context:** pack cache 的磁碟 spill 以 ObjectHash hex string 產生臨時路徑（src/internal/pack/cache.rs:133-140），SHA-256 與 BLAKE3 同為 64 hex，跨 kind 混用同一 spill 目錄可能命中彼此的殘留文件。
- **Decision:** cache spill 路徑必須以顯式 HashKind namespace（按 kind 分目錄或在路徑中帶 kind 前綴）隔離；由 B3-05 統一實現，BLAKE3 與 SHA-1/SHA-256 各自只讀取自己 namespace 的 spill。
- **Alternatives considered:** 沿用 raw hex 不加 namespace 會在混合 kind 的進程/工作樹中誤讀 spill 殘留；禁用 BLAKE3 spill 則造成性能回退，均拒絕。
- **Revisit when:** cache spill 改為帶 algorithm metadata 的容器格式。

### ADR-GI-B3-06: 0.9.0 minor 版本的 semver 兼容窗口

- **Status:** Accepted
- **Context:** HashKind（src/hash.rs:31-35）、ObjectHash（src/hash.rs:95-98）與 HashAlgorithm（src/utils.rs:70-74）均非 `#[non_exhaustive]`；新增 variant 對下游窮舉 match 是編譯面破壞。本計劃版本為 0.x（0.8.7 -> 0.9.0）。
- **Decision:** 0.x 階段以 minor 位作為 breaking 釋放點：B3-08 將版本從 `0.8.7` bump 至恰好 `0.9.0`，並在 release note 與 B3-07 handoff 文件中提供 migration note（列明 HashKind/ObjectHash/HashAlgorithm 新增 variant 對窮舉 match 的編譯影響與 B3-01 context API 的遷移路徑）。不使用 `#[non_exhaustive]`（會同時阻止下游在自身 crate 內建構 value，屬於更大的 API 限制）。下游在 0.9.0 升級時按 minor 視為潛在 breaking，顯式檢視 migration note。
- **Alternatives considered:** 以 patch 位發布 breaking 變更違反 semver 語義；等 1.0 再引入 BLAKE3 則無法支撐 Libra 版本管理流程的時程，均拒絕。
- **Revisit when:** git-internal 進入 1.x，需改用 major 版本與 `#[non_exhaustive]`/enum 輔助 API 評估。

## 全局工程約束

- **GC-01 現狀核實前置:** 每張卡開工先刷新源碼、測試、文檔與 Cargo target 錨點；已實現則改為補測、補文檔或關閉。
- **GC-02 單一事實源:** HashKind 的 size、hex_len、name、digest factory、explicit ObjectHash constructors 與 tagged parser 只能由 hash/utils 提供；呼叫端不得複製演算法判斷。
- **GC-03 Git 互操作邊界:** SHA-1/SHA-256 的既有 Git-compatible 行為保持；BLAKE3 明確標為 git-internal/Libra extension。
- **GC-04 ID 無歧義:** raw ID 只能在明確 repository HashKind context 下解析；跨 context 的資料必須使用 tagged ID 或 algorithm 欄位。
- **GC-05 AI 邊界:** IntegrityHash 固定 SHA-256；不可用 ObjectHash::kind() 取代。
- **GC-06 thread-local:** thread-local 只作既有單一 repository 工作流的相容預設；新增或修改的 worker、stream、cache、object loader、protocol callback 必須傳遞正確 kind，不得依賴可能屬於另一 repository 的執行緒預設。
- **GC-07 SHA 回歸:** 每張實作卡都保留 SHA-1 與 SHA-256 focused tests；不改變既有 raw Display、40/64 舊 parser 行為，除非本計劃明確增加 context API。
- **GC-08 fail-closed:** 長度不符、tag/kind 不符、pack trailer 不符、未知 object-format、跨 repository kind 不符均回傳錯誤，不做 SHA-1 fallback。
- **GC-09 生產 panic 禁止:** 不新增裸 unwrap、expect 或 panic；錯誤要帶 operation、kind 與 expected/actual length。
- **GC-10 性能預算:** object ID 計算維持 O(n) 串流/固定輸出；pack decode/encode 不因 BLAKE3 新增無界 buffer 或第二次全量掃描。
- **GC-11 測試隔離:** 測試設定 thread-local HashKind 必須使用現有 guard；並行測試不能依賴前一測試留下的 kind。
- **GC-12 下游只移交:** 本計劃不直接修改 Libra/Monoengine；下游使用 B3-07 的契約文件和已發布 git-internal 版本。
- **GC-13 wire 與 tagged boundary:** standard-like wire 只使用 repository kind 已驗證的 raw lowercase hex；tagged ID 不得直接寫入 pack、tree/commit payload 或 pkt-line。
- **GC-14 ER-13 全量門網路依賴:** 全量測試的 pack fixtures 由遠端按需下載（helper：src/internal/pack/test_pack_download.rs 的 `download_pack_file`；消費點以 `rg -n 'download_pack_file\(' src tests` 列出；helpers 位於 src/internal/pack/test_pack_download.rs 與 tests/common/mod.rs；消費測試分布在 src/internal/pack/decode.rs、src/internal/pack/stats.rs、src/internal/pack/encode/tests.rs、src/hash.rs tests、tests/decode-index-pack.rs；rg 輸出需排除 helper 定義行與非測試 helper（decode.rs 的 run_decode_*、encode/tests.rs 的 get_entries_for_test*、tests/decode-index-pack.rs 的 decode_pack），離線 skip 清單由消費點所屬測試函數名逐一對應；位於上述非測試 helper 的消費點，以其呼叫鏈上的測試函數名登記），`cargo test --all` 需要網路。decode.rs 有 6 個遠端大 fixture 測試已標 `#[ignore = "requires large remote pack fixture"]`（含 test_pack_check_header，本不在全量門內，離線 --skip 清單不需納入）。離線環境執行收口門時：先以 `cargo test --all -- --list` 取得測試清單，對消費 `download_pack_file` 的具名測試逐一 `--skip <name>`，記錄完整跳過清單與不可重現原因，聯網後補跑完整 `cargo test --all`；不得宣稱離線結果等同全量通過。若收口時離線跳過清單非空，必須在完成判據記錄前補跑成功。

## 性能與容量摘要

| 操作 | 單次成本 | 累積成本 | 預算/上限 | 驗證 |
|---|---|---|---|---|
| object hash | BLAKE3 O(n)，固定 32 bytes output | 隨 object payload 線性 | 不得第二次全量掃描 | hash vectors |
| loose object ID | 64 hex path，較 SHA-1 多 24 chars | metadata/path 增長固定 | 不改 object payload memory bound | object tests |
| pack trailer | 串流 BLAKE3 update | 每 pack 一次 O(pack bytes) | 不增加無界 buffer | pack round-trip |
| idx v2 object names | 32 bytes/object，較 SHA-1 多 12 bytes | O(object count) index 增長 | fanout/offset 結構不變 | idx fixture/stat |
| protocol capability | O(capability count) | 每次 protocol handshake 一次 | 不掃描 pack payload | protocol tests |
